画 MOS 管电路的地方。做模拟前端的人大概都试过用 PPT 画晶体管级原理图——拖一个方块出来，复制八个，改一下 W/L 发现标注全叠在一起。PPT 有形状，没有「栅极」和「衬底」的概念；而这张图里真正要紧的恰恰是每管的 W/L/Vt 和栅极怎么连。

这个工具让你**改数据，而不是画图**。正交走线是算出来的，端口坐标是查表得来的，导出是同一套渲染器重新输出一次。

## 元件库

- **N 管 / P 管** —— 四端（带独立衬底）或三端（体短接）。衬底箭头方向是判断沟道类型的硬依据：NMOS 指向沟道、PMOS 背离，画错整张图就废了
- **无源** —— IEC 矩形电阻、电容（含极性）、二极管、稳压管
- **电源与激励** —— 理想电压源、电流源、VDD / VSS 引出，带电平标注（3.3V / 1.8V）
- **连接与标注** —— 信号引出脚、接点圆点、跨线跳线弧、网络标签

## 旋转是对的，不是把图形拧一下

按 `R` 旋转。**符号只有 rot=0 一份 path，旋转靠 SVG transform**——不预渲染四个朝向。好处不只是省代码：端口世界坐标由同一个变换函数算出，所以**图形和端口在结构上不可能错位**。PMOS 的栅极气泡和衬底箭头都在被旋转的组里，跟着图形一起转，语义自动保持。

只有标注（型号 / W / L / Vt）不旋转——这几个字是工程师最在意的，绝不能倒过来。它们在旋转组**之外**，按世界坐标定位。

## 曼哈顿走线

连线**只存端口引用 + 拐点数组，不存绝对坐标**。移动管子时所有连线自动跟随，永不脱节。

路径生成后过一道 `orthoFix()`：元件移动后拐点不再构成直角时，自动补成 Z 形。**这条「每段都严格水平或垂直」是硬不变量**，由 500 组随机坐标的断言守着。

## 栅极列对齐

画 MOS 电路最花时间的两件事：让一堆管子的栅极落在同一垂线上，让所有 VDD 在同一水平线上。手动拖是折磨。

所以吸附优先级是**端口 > 栅极列 > 电源轨 > 网格**，前两档命中时画一条青色参考虚线贯穿画布，明确告诉你「你正在对齐到这一列」。方向键还能 1 格微调（Shift 加速 5 格）。

## 预设不是标准单元库

CMOS 反相器、NMOS 差分对、NMOS 电流镜、共源放大器、栅极 ESD 保护、施密特触发器——给的是**合理起点，不是 datasheet**。目的是省掉每次从零摆管子那一段。

差分对和电流镜的 W/L 按典型比例填好，放大倍率可以直接改。

## 导出自包含

**SVG 是核心输出。** 所有样式写成 presentation attribute，不含 `<style>` 块、不用 class、不引用外部资源，颜色 token 在导出时解析成实际 hex。这样 .svg 拖进 PowerPoint、Figma、Illustrator 不会因为找不到样式变成一团黑。

PNG 走 2 倍栅格化。另有 JSON 导入导出做备份分享。

## 几个技术选择

**全 SVG 而非「SVG 线 + HTML 元件」。** 逻辑电路工具用后者，因为它的元件不旋转、端口是固定 DOM。MOS 符号不是——它要整体旋转、要随端口吸附。所以走全 SVG，代价是端口命中测试要自己做屏幕↔世界换算，这个换算用 `getScreenCTM()` 而不是手算（浏览器保证它和实际渲染矩阵一致），并有一条断言守两者一致。

**文字宽度按中英文分别估算。** 中文按全宽、ASCII 按半宽。统一乘 0.6 的话，一行中文标注的包围盒会明显偏小，导出时右边被裁掉。

**纯逻辑层零 DOM。** `src/lib/mos/` 下的符号几何、正交布线、状态与撤销、网络分析全是无依赖纯函数，**1264 条断言**覆盖旋转矩阵可逆性、符号尺寸不变式、悬空诊断、撤销不变量、导出自包含性、脏数据归一化。用 esbuild bundle 后交给 node 直接跑，出错时读断言比在页面上猜快得多。

**悬空端口自动标红。** 栅极忘接是 MOS 电路里最常见也最难一眼看出的错误。工具每次改动都会重算网络表，把没接线的端口圈出来——这个提示会跟着导出一起进 SVG，贴进论文前能再扫一遍。

## 踩过的坑

写这个工具时抓到的几个问题，都属于「不报错但行为是错的」那一类：

- **并查集里不能把元件节点和它所有端口 union。** 早先图省事这么做了，结果「栅极接上线」会让同一元件的漏极源极也变成已连接——悬空诊断全部失效，所有管子的 d/s 都不再标红。连通性只能在端口之间算。
- **`orthoRoute` 的退化路径一开始也做 STUB 直出。** 两端已经水平对齐时，加直出只会多出两个共线点，视觉上看不出区别，却让清理后仍残留 3~4 个顶点。已对齐就该直接返回一段直线。
- **拖拽状态用 discriminated union 而不是一堆可选字段。** 之前 `fromPort: Endpoint | null` 全局可选，结果每个赋值点都要补 `fromPort: null, fromDir: 'U'`——而这两行在平移拖拽里毫无意义，漏写就报错。
- **预设的 ID 计数器必须每次重置。** 否则第二次构建同一预设时 ID 继续往上走，症状是「载入同一预设两次，两张图的元件 ID 不一样」，数组复制粘贴全乱。
